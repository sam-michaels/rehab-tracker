# ADR 0007: Evaluation harness — four ground-truth tiers, Bland–Altman reporting, derived data only

- **Status:** Accepted
- **Date:** 2026-09-21
- **Deciders:** Project owner
- **Builds on:** ADR 0001 (decoupled harness, device-independent cost measure), ADR 0003
  (paired offline/online reporting), ADR 0004 (projection lab and its ordering), ADR 0005
  (session archive import, cross-language fixtures), ADR 0006 (containerized runners, common
  keypoint-series format, parity gate, macOS requirement)

## Context

### The ground truth has its own noise floor

Manual goniometry of the ankle has published inter-rater reliability on the order of **±5°**.
Any accuracy figure expressed as error against a goniometer is therefore bounded by the
goniometer's own repeatability, and a figure reported without knowing that repeatability is
uninterpretable. If the system lands within goniometer noise, the correct conclusion is not
"the system is accurate" but "this comparison is exhausted and cannot resolve further".

### A single error number is not actionable

Measured error has separable sources: keypoint localization error; angle-definition error,
since a COCO keypoint is an annotation convention rather than an anatomical joint centre;
projection error from camera placement; temporal error from causal filtering; and the
reference instrument's own error. A goniometer alone cannot distinguish them. Given ADR 0006
records that the MVP has **no remediation path through training**, the ability to attribute a
poor result to a specific cause is what determines whether it can be acted on at all.

### Inherited requirements

This decision is the most constrained in the project. It must: orchestrate containerized
per-model runners emitting a common keypoint-series format (ADR 0006); host the conversion
parity gate (ADR 0006) and the cross-language pipeline fixtures (ADR 0005); report paired
offline and online results (ADR 0003); implement the projection lab under its stated ordering
(ADR 0004); import session archives from the device (ADR 0005); and run on macOS, since it
executes the shipped Core ML artifact (ADR 0006).

## Options considered

### 7a — Ground-truth strategy

| Tier | Method | Error source isolated |
|---|---|---|
| T1 | Rigid articulated jig at known set angles, filmed | Pipeline geometry, with no anatomical ambiguity |
| T2 | Coloured markers on landmarks, auto-tracked over ~100 frames | Keypoint localization, separated from angle definition |
| T3 | Goniometer, and shin inclinometer for the lunge test, on held positions | The clinically meaningful claim |
| T4 | UI-PRMD / KIMORE projected at known camera poses | Camera-angle sensitivity |

Two properties of T3 are worth recording. A goniometer cannot measure a moving ankle, but the
reported quantity is *peak* range of motion, which is a held extreme — so static ground truth
matches the claim rather than approximating it. And for the weight-bearing lunge, an
inclinometer on the shin is not a proxy for the clinical instrument; it **is** the clinical
instrument, so continuous ground truth is available for that exercise specifically.

Options ranged from T3 alone (fastest to the headline number, but any poor result is
unattributable), through T1 plus T3 (answers the go/no-go with basic attribution), to all four
tiers built before the first accuracy number is produced.

### 7b — Report production

A script emitting markdown and plots into a versioned directory, regenerated by one command;
a Jupyter notebook; or an HTML dashboard. The first diffs in git, so accuracy movement is
visible across commits, and renders directly on GitHub — which matters because ADR 0001
established that the repository, not a deployed app, is the portfolio artifact. Notebooks do
not diff, do not automate, and carry stale output state.

### 7c — What the repository contains

Test clips are video of a person in a health context, and cannot go into a public repository.
Options were: derived data only; derived data plus a small consented public subset; or
everything via git-lfs.

## Decision

**All four ground-truth tiers; script-generated markdown reports committed to the repository;
derived data only, with clips held locally.**

The recommendation presented was T1 plus T3 first, on the grounds that they answer the
project's go/no-go question soonest and that ADR 0006's lack of a remediation path makes early
resolution valuable. The owner chose all four up front, accepting a later go/no-go in exchange
for a result that is immediately attributable rather than one that triggers a week of building
diagnostics after the fact. That trade is recorded in Consequences.

### Condition 1 — repeatability before accuracy

The first measurement taken is not the system's error but the **goniometer's own**: repeated
measures of the same held position, yielding standard error of measurement and minimal
detectable change. No accuracy claim about the system is stated before this floor is known,
and every subsequent claim is reported against it.

### Condition 2 — T4 machinery now, T4 results after T3

ADR 0004, Condition 4 fixed the sequence: projected skeletons are unrealistically clean and
require noise matched to RTMPose's measured error distribution, which comes from T3.
"Up front" therefore means the projection code and camera-pose sweep are built immediately,
with the noise model as an unpopulated parameter. Any T4 output produced before T3 data exists
is labelled provisional in the report. This preserves the decision without violating the
accepted ordering.

### Condition 3 — Bland–Altman, with bias and limits of agreement reported separately

Method comparison is reported as bias and 95% limits of agreement, not as a single error
figure and not as a correlation coefficient. The distinction is practical rather than
stylistic: **systematic bias is correctable by calibration, random spread is not**, and a
single MAE conceals which one is present. Correlation is excluded explicitly — two methods can
correlate at 0.98 while disagreeing by ten degrees.

### Condition 4 — rep detection reported as precision and recall

Not as count accuracy. A count can be correct through a missed rep cancelling a spurious one,
which conceals two failures as one success.

### Condition 5 — performance reported with a device-independent measure

Per ADR 0001: latency and frame rate against the named device, **plus** model MACs and
CPU-only latency, so the figure means something to a reader with different hardware.

### Condition 6 — every report is paired offline and online

Per ADR 0003, Condition 6: the non-causal Savitzky–Golay and peak-detected result alongside
the causal One Euro and state-machine result, on the same clips, with the difference stated as
the cost of real-time processing.

### Condition 7 — CI runs fixtures, not the full report

Fast fixtures run on every push: cross-language pipeline agreement (ADR 0005, Condition 4) and
conversion parity (ADR 0006, Condition 4). The full accuracy report is a manual or tagged run.
Nightly infrastructure for a corpus of tens of clips is not built.

### Condition 8 — no clip without a manifest entry

Each clip records exercise, subject, camera position and height, distance, footwear, lighting,
background and device. A clip lacking this metadata cannot be interpreted and is not part of
the corpus. Camera position in particular is the variable T4 exists to characterize; unrecorded,
it becomes an unattributable confound.

## Consequences

### Positive

- A poor result is attributable to a specific stage rather than to the system as a whole,
  which is what makes it actionable given the absence of a training-based remedy.
- The accuracy claim is bounded honestly by the reference instrument's repeatability instead
  of implying precision the comparison cannot support.
- Bland–Altman reporting is what a clinically literate reader expects, and separates the
  correctable error from the irreducible one.
- Reports are diffable, so accuracy changes are visible across commits, and readable on GitHub
  where the portfolio value lies.
- The harness exercises the shipped artifact through the same runners and formats the app uses,
  so its numbers describe the deployed system.

### Negative — accepted

- **The go/no-go on the project premise arrives later.** Building four tiers before the first
  accuracy number defers the moment the core research question is answered, and ADR 0006
  established there is no remediation path if it resolves negatively. The compensating benefit
  is that the answer arrives already decomposed.
- Four tiers are four things to build and maintain, and some may never earn their keep. If T1
  and T3 agree closely, T2 will have been redundant. This is accepted as insurance rather than
  justified as necessity.
- The goniometer floor may cap the headline claim. A result of "within the repeatability of the
  reference instrument" is the best outcome available and is less quotable than a small number.
- Derived-data-only means a third party can reproduce the analysis but not the inference. This
  is stated plainly in the README rather than left for a reader to discover.
- **The corpus is one subject.** Every figure characterizes this system on one person's ankle,
  one body type, one skin tone, one set of lighting conditions. This is a pilot, not a
  validation, and must be labelled as such. Pose estimation models have documented performance
  disparities across skin tone and body habitus; an n=1 corpus cannot assess them, and the
  report must say so rather than let generality be inferred. What a real validation would
  require — multiple subjects, varied skin tones and body types, footwear conditions — belongs
  in the report's limitations section from the first version, not added later.

### Follow-ups this decision creates

- **Decision 8 (repo structure)** must place the harness, per-runner containers, fixtures,
  manifest schema and versioned report directory, alongside the shared schema ADR 0005
  requires, and must accommodate a macOS-only CI job for the artifact-executing tests.
- A clip capture protocol is needed before recording begins: camera positions to sweep,
  distances, repetitions per condition, and how held positions are cued for T3.
- Deliberately incorrect-form clips with labelled faults are required to test rules
  (ADR 0004 follow-up), and their capture protocol is separate from the accuracy corpus.
- The README needs a limitations and privacy section stating the n=1 corpus, the
  derived-data-only policy, and the absence of clinical validation.
